01

What Midas is

Midas is a from-scratch rebuild of the Kalshi prediction-market trading bot. The legacy bot was audited in April 2026 and found to have structural bugs (bankroll only goes up, dead reconciliation, dead strategies, magic numbers, no test coverage). The architecture v2 document committed to a multi-service event-driven system inspired by hedge-fund OMS/EMS/Risk separation. Midas is being built deliberately, slowly, and well — explicitly avoiding the patterns that broke the legacy bot.

The goal is "as close to hedge-fund-grade as a two-person team can build" — not literally Citadel, but a system that a knowledgeable observer would call professional work.

The legacy bot remains paused. If trading resumes during the Midas build, it does so on the legacy bot with audit fixes applied — not on the half-built new system.

For the narrative arc — why each phase exists, what it enables, why the order matters — see docs/JOURNEY.md. This handoff document tells you the what and where; the journey document tells you the why.

The 10 binding constraints

From docs/LESSONS_FROM_OLD_BOT.md, captured in v2 §4. Not suggestions. If a proposal violates one of them, push back.

  1. Bankroll only goes up — use event sourcing, not mutable balance fields
  2. Reconciliation never ran — must be on a scheduler
  3. Strategies as strings — use ClassVar + __init_subclass__ enforcement
  4. Eight strategies, two of which were dead code — delete what isn't deployed
  5. Risk gates duplicated in eight places — one canonical implementation only
  6. Shadow drifted into research lab — paper environment ≠ research
  7. State file 34 keys deep with no schema — Pydantic + JSON Schema, versioned
  8. The learning system never learned — every event has a reader
  9. Magic numbers everywhere — config in YAML, not code
  10. The bot grew faster than its tests — tests not optional, CI gates
