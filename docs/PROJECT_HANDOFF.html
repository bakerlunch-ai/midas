01

What Midas is

Midas is a from-scratch rebuild of a Kalshi prediction-market trading bot. The previous bot (in ~/Desktop/...kalshi-bot/, paused) reached ~5,300 lines in one Python file with multiple structural bugs (bankroll only goes up, dead reconciliation, dead strategies). The audit synthesis documented those failures. The architecture v2 document ("Bot Architecture v2 — Professional Grade Rebuild") committed to a multi-service event-driven system inspired by hedge fund OMS/EMS/Risk separation.

Midas is being built deliberately, slowly, and well — explicitly avoiding the patterns that broke the old bot. The 10 lessons from docs/LESSONS_FROM_OLD_BOT.md are binding constraints, not suggestions.

Eventual architecture (target state, not current)

  • data-svc — ingest market data, FRED, news, Claude AI edge analysis
  • strategy-* services — one per strategy (TIMELY, MIDSEL, ARB, etc.), independent deploys
  • risk-svc — single point for all risk gates and Kelly sizing
  • oms-svc — order lifecycle, event-sourced ledger, daily reconciliation
  • ems-svc — execution against venues, two modes: live and paper
  • pms-svc — positions, P&L, bankroll, event-sourced
  • reporting-svc — dashboards and reports
  • telegram-svc — human interface (alerts, commands)
  • mcp-svc — exposes the bot as an MCP-compatible server for AI agents

All services communicate via NATS JetStream. Two PostgreSQL event-sourced ledgers (orders, portfolio). LGTM observability stack (Loki, Grafana, Tempo, Prometheus). Managed Kubernetes (DOKS).

The 10 binding constraints

From docs/LESSONS_FROM_OLD_BOT.md. If a proposal violates one of these, push back, name the lesson, suggest the alternative, ask before proceeding.

  1. Bankroll only goes up — use event sourcing, not mutable balance fields
  2. Reconciliation never ran — must be on a scheduler
  3. Strategies as strings — use ClassVar + __init_subclass__ enforcement
  4. Eight strategies, two of which were dead code — delete what isn't deployed
  5. Risk gates duplicated in eight places — one canonical implementation only
  6. Shadow drifted into research lab — paper environment ≠ research
  7. State file 34 keys deep with no schema — Pydantic + JSON Schema, versioned
  8. The learning system never learned — every event has a reader
  9. Magic numbers everywhere — config in YAML, not code
  10. The bot grew faster than its tests — tests not optional, CI gates
