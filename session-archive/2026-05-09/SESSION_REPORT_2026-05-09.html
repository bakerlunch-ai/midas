Task 7 — Wire it all into FastAPI lifespan (commit b6bed38)

Why it matters: the most architecturally-significant code on the branch. Lifespan-managed dependencies = startup fail-fast, deterministic teardown order. Pattern: settings → checks → resource connections → spawn background tasks → yield → cancel tasks → close resources. Every Phase 2 service uses this template.

  • Settings instantiated at lifespan entry (NOT module import) — keeps tests that bypass lifespan from crashing on missing env vars
  • Startup order: Settings() → check_postgres → check_redis → nats.connect → asyncio.create_task(_heartbeat_loop)
  • Shutdown order (reverse): cancel heartbeat task → await it → nc.close() — order matters so the task stops trying to publish before NATS closes
  • _heartbeat_loop re-raises CancelledError; lifespan teardown swallows it via contextlib.suppress(CancelledError) — modern asyncio convention (task ends up marked Cancelled, not CompletedNormally)
  • 3 tests using TestClient as context manager (which exercises lifespan): order verification, shutdown teardown verification, startup-failure propagation verification
  • Total: 22 tests passing (5 base + 7 heartbeat + 1 health + 2 publish_heartbeat + 2 postgres + 2 redis + 3 lifespan)

How this fits the v2 architecture (plain English)

The kitchen analogy

Imagine the v2 architecture as a restaurant. The previous bot was a single chef in a kitchen with a hot plate and a knife — making everything from scratch in one pan, getting confused about what's medium-rare, dropping orders on the floor. Midas is the rebuild: separate stations (data prep, sauté, grill, plating) with proper tickets passing between them.

Phase 1 has been building the kitchen itself: the gas line (NATS), the walk-in fridges (Postgres, Redis), the surveillance cameras and order display (LGTM stack), the locked cabinet for sealed-secrets, the dumbwaiter (Argo CD) connecting orders to plates.

Tonight we hired a stagiaire — hello-svc — who isn't a real chef yet, but who has to walk into the kitchen, find the fridges, log into the cameras, send a "I'm here" ticket every minute, and not catch fire. The stagiaire passed. The kitchen works. Phase 2's actual chefs (data-svc, oms-svc, pms-svc) can start their shift knowing every station functions.

05

Issues + resolutions

Pytest basename collision (test_heartbeat.py in two packages)

Resolution: added addopts = "--import-mode=importlib" to root pyproject.toml. Structural fix; both files coexist cleanly. Future Phase 2 services can name files however they want.

doctl 1.158.0 removed --kubeconfig flag

Resolution: use KUBECONFIG=path doctl kubernetes cluster kubeconfig save midas-prod instead. Documented in carry-items for the runbook.

Credentials leaked in chat transcript

Issue: ran kubectl get secret X -o jsonpath='{.data}' to verify field names; this returned base64-encoded VALUES too, exposing the full Postgres + Redis connection strings (with passwords) into chat. Resolution: Filippo chose to skip rotation tonight (VPC-only access mitigates; not blocking). Better future command documented: kubectl get secret X -o go-template='{{range $k,$v := .data}}{{$k}}{{"\n"}}{{end}}' — keys only, no values. Rotation added to carry items.

GHCR package was private; pod stuck in ImagePullBackOff with 401

Resolution: Filippo flipped visibility to Public in GitHub Danger Zone. kubectl delete pod -l app=hello-svc forced an immediate retry; cluster pulled the image. Curious side note: Filippo's local docker manifest inspect still returned 401 even after the flip succeeded for DOKS — probable GHCR routing/cache quirk, deferred as a carry item.

Two transient cluster API EOF errors during the Argo apply window

Cluster events showed kube-scheduler, kube-controller-manager, and cluster-autoscaler all re-electing leaders ~20s before, suggesting a brief DOKS managed-control-plane reshuffle. Cluster API recovered on its own. Resolution: retried the kubectl call; worked. Not related to hello-svc.

Pod scheduling took ~90s instead of expected ~5s

Same root cause as above — managed control plane was mid-reshuffle. The kubelet picked it up once the scheduler's lease re-stabilized. Resolution: patience.
