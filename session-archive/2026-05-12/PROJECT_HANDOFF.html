01

What Midas is

Midas is a from-scratch rebuild of a Kalshi prediction-market trading bot. The previous bot reached ~5,300 lines in one Python file with multiple structural bugs (bankroll only goes up, dead reconciliation, dead strategies). The audit synthesis documented those failures. The architecture v2 document committed to a multi-service event-driven system inspired by hedge fund OMS/EMS/Risk separation.

Midas is being built deliberately, slowly, and well — explicitly avoiding the patterns that broke the old bot. The 10 lessons from docs/LESSONS_FROM_OLD_BOT.md are binding constraints, not suggestions.

All 7 events follow the BaseEvent pattern (frozen=True, extra="forbid", ClassVar event_type/event_version with __init_subclass__ enforcement, wrap serializer for class constants). Decimal-in-cents for prices, Decimal-in-dollars for money. No floats. Order-level facts not duplicated across events (event-sourcing discipline; consumers join via exchange_order_id). Realized P&L pre-computed on PositionClosedEvent so reporting/risk/learning don't replay fill chains.

08

The 10 binding constraints

These are not suggestions. If a proposal violates one, Claude names the constraint, suggests the alternative, asks whether to proceed. Source: docs/LESSONS_FROM_OLD_BOT.md.

  1. Bankroll only goes up — use event sourcing, not mutable balance fields
  2. Reconciliation never ran — must be on a scheduler
  3. Strategies as strings — use ClassVar + __init_subclass__ enforcement
  4. Eight strategies, two dead code — delete what isn't deployed
  5. Risk gates duplicated in eight places — one canonical implementation
  6. Shadow drifted into research lab — paper environment ≠ research
  7. State file 34 keys deep with no schema — Pydantic + JSON Schema, versioned
  8. The learning system never learned — every event has a reader
  9. Magic numbers everywhere — config in YAML, not code
  10. The bot grew faster than its tests — tests not optional, CI gates
