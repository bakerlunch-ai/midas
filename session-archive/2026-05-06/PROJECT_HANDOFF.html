01

What Midas is

Midas is a from-scratch rebuild of the Kalshi prediction-market trading bot. The legacy bot (~5,300 lines, audited April 2026) is paused — it has structural bugs (bankroll only goes up, dead reconciliation, magic numbers, no event sourcing). Architecture v2 committed to a multi-service event-driven system inspired by hedge-fund OMS/EMS/Risk separation, deployed on Kubernetes via GitOps.

Midas is being built deliberately, slowly, and well — explicitly avoiding the patterns that broke the legacy bot. Total realistic timeline: 5–6 months calendar time across 8 phases, evening/weekend work.

Where we are right now: Phase 1 (infrastructure foundation), 9.5 of 12 tasks complete. No services running yet. No trading code written yet. We're still building the empty building before the kitchens, recipes, and chef arrive.

The kitchen analogy

Think of v2 as a professional kitchen with eight stations (the eight services in §04: data, oms, pms, strategy, risk, reporting, scheduler, mcp-gateway). For these stations to function, the building needs four foundation pieces:

  • The building itself — Kubernetes cluster + databases + repo + CI (§07). Done — Phase 1 Tasks 1–6
  • The locked supply room — sealed-secrets for credentials (§07). Done — Phase 1 Task 7
  • The kitchen intercom — NATS JetStream for service-to-service events (§05). Done — Phase 1 Task 9
  • The cameras & microphones — observability: Loki + Tempo + Prometheus + Grafana (§07). Half-done — Loki and Tempo running, Prometheus stack stuck

The kitchen has zero chefs yet. No services from §04 are running. No trading code exists. Every line of business logic is still ahead. This is correct sequencing — v2 explicitly orders infrastructure before services to avoid the legacy bot's failure mode (services built on broken foundations).

Decisions on record

  • GitOps via Argo CD — every cluster change goes through git first, Argo CD syncs.
  • Helm charts pinned to specific versions in every Application — no moving tags.
  • Sealed Secrets via Bitnami sealed-secrets — controller in sealed-secrets namespace, files in deploy/secrets/ are encrypted, safe to commit.
  • Credentials canonical pattern: doctl CLI, never the DigitalOcean web UI copy buttons — see section 06.
  • Each Helm chart Application owns its own namespace via CreateNamespace=true. App-of-Apps deferred until 10+ Applications.
  • NATS JetStream as the message bus — 3-replica file-store cluster. Backbone of event-sourced architecture in v2.
  • LGTM stack for observability — Loki (logs), Grafana (UI), Tempo (traces), kube-prometheus-stack (metrics). All in monitoring namespace.
  • DOKS-incompatible scrapers disabled in kube-prometheus-stack values: kubeEtcd, kubeControllerManager, kubeScheduler, kubeProxy.
  • VPC-only network access for managed databases. Public network disabled.

Credential sealing — canonical pattern

Never use DigitalOcean's web UI copy buttons. They capture hidden DOM state and produce broken connection strings. Always use doctl CLI.

Postgres user credentials

# Replace placeholders with real values: # <user> = oms_user | pms_user | reporting_user # <db> = oms_db | pms_db | reporting_db # <name> = oms | pms | reporting (used for the file names) doctl databases user get f1c361f7-4e4c-4f4e-a7b6-3ee6f81cbd7d <user> --format Password --no-header > /tmp/<name>-pw.txt HOST=$(doctl databases connection f1c361f7-4e4c-4f4e-a7b6-3ee6f81cbd7d --private --format Host --no-header) PORT=$(doctl databases connection f1c361f7-4e4c-4f4e-a7b6-3ee6f81cbd7d --private --format Port --no-header) PASSWORD=$(cat /tmp/<name>-pw.txt | tr -d '\n') echo -n "postgresql://<user>:${PASSWORD}@${HOST}:${PORT}/<db>?sslmode=require" > /tmp/<name>-conn.txt unset HOST PORT PASSWORD

Redis (Valkey) credentials

# doctl databases user get returns 404 on Valkey clusters. # Use the connection URI command instead — it includes the password. doctl databases connection 8671e021-fe36-4354-915b-731be8dc9602 --private --format URI --no-header | tr -d '\n' > /tmp/redis-conn.txt

Verify before sealing (mandatory step)

wc -c /tmp/<name>-conn.txt # expect 110-180 bytes wc -l /tmp/<name>-conn.txt # expect 0 (no trailing newline) sed 's/[A-Za-z0-9!#$%^&*()_+=-]\{6,\}/REDACTED/g' /tmp/<name>-conn.txt # expect: REDACTED://REDACTED:REDACTED@REDACTED...:25060/REDACTED?REDACTED # Note: @ MUST be visible. Regex omits @ from char class on purpose.

Seal and verify

KUBECONFIG=~/.kube/config-midas kubectl create secret generic <secret-name> --dry-run=client \ --from-file=<ENV_VAR>=/tmp/<name>-conn.txt -n default -o yaml | \ KUBECONFIG=~/.kube/config-midas kubeseal --controller-namespace=sealed-secrets \ --controller-name=sealed-secrets-controller --format=yaml > ~/Desktop/midas/deploy/secrets/<secret-name>.yaml # Apply & verify decoded structure: KUBECONFIG=~/.kube/config-midas kubectl apply -f ~/Desktop/midas/deploy/secrets/<secret-name>.yaml KUBECONFIG=~/.kube/config-midas kubectl get secret <secret-name> -n default \ -o jsonpath='{.data.<ENV_VAR>}' | base64 -d | wc -l # expect 0 # Clean up the raw temp files: rm /tmp/<name>-pw.txt /tmp/<name>-conn.txt
Mandatory: Apply and decode-verify each sealed file before moving on to the next credential. Sealing without verifying is what produced the broken May-4 oms file.

The 10 binding constraints

Lessons from the legacy bot audit. Encoded in docs/LESSONS_FROM_OLD_BOT.md. If a proposal violates one of these, push back.

  1. Bankroll only goes up — use event sourcing, not mutable balance fields
  2. Reconciliation never ran — must be on a scheduler
  3. Strategies as strings — use ClassVar + __init_subclass__ enforcement
  4. Dead code — delete what isn't deployed
  5. Risk gates duplicated — one canonical implementation
  6. Shadow drifted into research lab — paper environment ≠ research
  7. Schemaless state — Pydantic + JSON Schema, versioned
  8. Learning system never read — every event has a reader
  9. Magic numbers — config in YAML, not code
  10. Tests not optional — CI gates from day 1

Glossary (for new chats)

Argo CDGitOps tool. Watches the repo and syncs cluster state. Polls every 3 min.
Helm chartA package of Kubernetes manifests with templated values. We pin versions for reproducibility.
SealedSecretAn encrypted Secret. Safe to commit to git. The cluster controller decrypts into a usable Secret on the fly.
NATS JetStreamPersistent message bus. Services publish events, others subscribe. Backbone of the event-sourced architecture.
LGTM stackLoki (logs) + Grafana (UI) + Tempo (traces) + Mimir/Prometheus (metrics). Observability bundle.
kube-prometheus-stackThe all-in-one Helm chart that bundles Prometheus, Grafana, Alertmanager, exporters. Currently broken on our cluster — see Plan B.
CRDCustomResourceDefinition. Lets Kubernetes know about new resource types (like ServiceMonitor). kps installs ~10 of these.
PVCPersistentVolumeClaim. A request for cluster storage. Each PVC binds to a real DigitalOcean block storage volume.
StatefulSetKubernetes controller for stateful clustered workloads (NATS, Loki, Tempo, Postgres if it were in-cluster).
Sync waveArgo CD annotation that controls which order Applications get applied. Negative numbers go first. Used to install CRDs before things that depend on them.
doctlDigitalOcean's CLI. Bypasses the web UI when needed. Critical for credential fetching after we hit the broken copy-button bug.
kubesealThe CLI tool that turns a regular Secret into a SealedSecret using the cluster's public key.
VPCVirtual Private Cloud. The internal network all our cluster + database traffic runs over. Public network access is disabled.
