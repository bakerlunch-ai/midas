01

What Midas is

A from-scratch rebuild of a Kalshi prediction-market trading bot as a multi-service, event-driven system on DigitalOcean Kubernetes — concerns separated like a hedge fund (data, orders, portfolio, risk, execution as distinct services on an event bus). The legacy bot (~5,300 lines, audited April 2026) had structural bugs (bankroll only went up, dead reconciliation, dead strategies, magic numbers). Midas is built deliberately to avoid those, governed by 10 binding constraints (§10). Legacy bot is paused. Realistic timeline: 5–6 months across 8 phases.

09

The 10 binding constraints

  1. Bankroll only goes up → event sourcing, not mutable balance fields
  2. Reconciliation never ran → must be on a scheduler (and: a gate nobody watches is no gate)
  3. Strategies as strings → ClassVar + __init_subclass__ enforcement
  4. Dead strategies → delete what isn't deployed
  5. Risk gates duplicated 8× → one canonical implementation
  6. Shadow drifted into research lab → paper environment ≠ research
  7. State file 34 keys deep, no schema → Pydantic + JSON Schema, versioned
  8. The learning system never learned → every event has a reader; verify with evidence, don't infer
  9. Magic numbers everywhere → config in YAML, not code
  10. The bot grew faster than its tests → tests not optional, CI gates (and the gate must actually gate)
