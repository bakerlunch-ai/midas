01

Why this session matters

⊹ Connection to the v2 architecture and the journey

This session was laying the foundation — both literally (cluster + database) and culturally (the discipline document, the strict event base class, the test setup, the structured handoff system).

The two big technical wins (cluster + Postgres) get most of the headlines, but the more important outputs of this session are the things that aren't infrastructure at all:

  • The 10 binding constraints in LESSONS_FROM_OLD_BOT.md — explicit, named, written-down rules from the audit. The legacy bot's worst failures all started as "reasonable shortcuts." Writing them down makes them refusable.
  • The strict BaseEvent class with ClassVar + __init_subclass__ enforcement — this directly closes Lesson #3 (strategies as strings). Python now refuses to load a malformed event subclass.
  • The four-document handoff system — the discipline that makes 5-6 month projects survive the "I forgot what we were doing" gap between sessions.

In v2 architecture terms, this session covered: Section 6 (data stores — Postgres provisioned), Section 7 (operational stack — Kubernetes cluster live), and the foundational discipline that Section 4 demands (no magic numbers, no schemaless state, tests not optional).

What this session did NOT yet enable: any service can actually be deployed to the cluster. That came in session 2 with Argo CD. April 29 built the cluster; May 4 built the way to use it.

For the full narrative arc, see docs/JOURNEY.md.

Collaboration notes

Filippo drove the DigitalOcean web UI; Claude (chat) walked through every form field and verified before each Create button click. Peter was present and active. Multiple times the UI auto-changed values when other fields were modified (region change reset machine type, switching CPU type reset plan tier) — every dropdown was re-verified after every other change to prevent surprises.

The session was longer than ideal (~3 hours) but produced more progress than expected. Two of twelve Phase 1 tasks complete, real infrastructure running, no regressions or rollbacks needed.

One process change came up mid-session: 2FA on the DigitalOcean account was initially declined, then enabled when its absence was flagged again before high-trust operations. The lesson: surface security questions early, and don't fight on them — re-raise them at the natural moment when their absence becomes load-bearing.
